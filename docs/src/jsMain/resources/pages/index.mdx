<ktjs-features section-title="Three modules, one rule" tinted>

<ktjs-feature icon="lucide:database" title="DuckDB in the browser">`ktjs-duckdb-wasm` types `@duckdb/duckdb-wasm`: the async database handle, connections, prepared statements, the file registry and the bundle selection helpers.</ktjs-feature>

<ktjs-feature icon="lucide:server" title="DuckDB on the server">`ktjs-duckdb-node-neo` types `@duckdb/node-api`: real threads and real files, with the CommonJS runtime export shape handled for you.</ktjs-feature>

<ktjs-feature icon="lucide:table" title="Results as Arrow">`ktjs-apache-arrow` types `apache-arrow`, the format DuckDB hands results back in — schemas, vectors, record batches and the IPC functions.</ktjs-feature>

<ktjs-feature icon="lucide:shield-check" title="Types, not `JsAny`">A `Type` enum member is not a `Double`, a `'file' | 'stream'` argument is not a `String`, and a column vector is typed by its values.</ktjs-feature>

<ktjs-feature icon="lucide:boxes" title="Split where upstream splits">The three packages run in different environments and evolve on different schedules, so the wrapper keeps them three modules instead of one bundle.</ktjs-feature>

<ktjs-feature icon="lucide:flask-conical" title="Tested against the real packages">The modules' tests run against the actual npm packages, not hand-written fakes.</ktjs-feature>

</ktjs-features>
