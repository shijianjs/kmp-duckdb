<ktjs-features section-title="三个模块，同一条规则" tinted>

<ktjs-feature icon="lucide:database" title="浏览器里的 DuckDB">`ktjs-duckdb-wasm` 声明 `@duckdb/duckdb-wasm`：异步数据库句柄、连接、预编译语句、文件登记与 bundle 选择辅助。</ktjs-feature>

<ktjs-feature icon="lucide:server" title="服务端的 DuckDB">`ktjs-duckdb-node-neo` 声明 `@duckdb/node-api`：真正的线程与文件，CommonJS 的运行时导出形状已经替你处理。</ktjs-feature>

<ktjs-feature icon="lucide:table" title="结果是 Arrow">`ktjs-apache-arrow` 声明 `apache-arrow`，也就是 DuckDB 返回结果所用的格式——schema、向量、record batch 与 IPC 函数。</ktjs-feature>

<ktjs-feature icon="lucide:shield-check" title="类型化，不是 `JsAny`">`Type` 枚举成员不是 `Double`，`'file' | 'stream'` 参数不是 `String`，列向量按它的值类型而不是按 `JsAny` 建模。</ktjs-feature>

<ktjs-feature icon="lucide:boxes" title="按上游边界拆分">三个包运行在不同环境、演进节奏也不同，所以封装保持三个模块，而不是捆成一个。</ktjs-feature>

<ktjs-feature icon="lucide:flask-conical" title="对着真实包测试">模块的测试跑在真实的 npm 包上，而不是手写替身。</ktjs-feature>

</ktjs-features>
