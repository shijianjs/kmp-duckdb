# kmp-duckdb

<p align="center"><img src="docs/src/jsMain/resources/static/img/kmp-duckdb-logo.png" width="120" alt="kmp-duckdb"></p>

Kotlin/JS wrappers for [DuckDB](https://duckdb.org/) and [Apache Arrow](https://arrow.apache.org/):
the WASM build that runs in a browser, the native Node client, and the Arrow package both of them
speak. Every wrapper is generated by hand from the upstream `.d.ts` files and checked by tests that
call the real library.

## Modules

| Module | npm package | Wrapper version |
| --- | --- | --- |
| [ktjs-apache-arrow](ktjs-apache-arrow/README.md) | `apache-arrow` 21.2.0 | `21.2.0-kt.1` |
| [ktjs-duckdb-wasm](ktjs-duckdb-wasm/README.md) | `@duckdb/duckdb-wasm` 1.32.0 | `1.32.0-kt.1` |
| [ktjs-duckdb-node-neo](ktjs-duckdb-node-neo/README.md) | `@duckdb/node-api` 2.0.0-r.1 | `2.0.0-r.1-kt.1` |

Arrow is the odd one out in the order: it is not a DuckDB package, but DuckDB hands its query results
back as Arrow tables, so a Kotlin consumer needs it before it can read a single row. That is also why
`ktjs-duckdb-wasm` depends on it while `ktjs-duckdb-node-neo` does not — the Node client returns native
JS values instead of Arrow.

## Using it

```kotlin
dependencies {
    implementation("io.github.shijianjs:ktjs-duckdb-wasm:1.32.0-kt.1")
}
```

The wrapper pulls in the upstream npm package itself, so no extra npm dependency is needed. See
[Getting started](https://shijianjs.github.io/kmp-duckdb/guide/getting-started) for a working query in
the browser and in Node, and the demo page for a live one.

## Versioning

Each module is versioned as `{upstream npm version}-kt.{revision}`. The upstream versions are declared
once in the root [`package.json`](package.json); the revision is read per module from
[`wrapper-revisions.properties`](wrapper-revisions.properties). Only `-kt.N` versions are published, a
working tree adds `-SNAPSHOT`, and revisions only ever increase.

## Requirements

- JDK 21 or newer (the build uses Gradle 9.4.1).
- Node and npm are downloaded by the Kotlin Gradle plugin; `kotlin.js.yarn=false` keeps npm as the
  package manager.
- Chromium is downloaded by Playwright the first time browser tests run.

## Build and test

```bash
./gradlew build                              # compile, Detekt, browser tests
./gradlew :ktjs-duckdb-node-neo:jsNodeTest    # the Node client, no browser needed
./gradlew :demo:e2eTest                       # Playwright against the bundled demo page
./gradlew :docs:docusaurusBuild               # the documentation site
./gradlew pagesSite                           # docs at the root, demo under /demo/, Dokka under /api/
```

## Repository layout

- `ktjs-apache-arrow`, `ktjs-duckdb-wasm`, `ktjs-duckdb-node-neo`: the published modules.
- `demo`: a browser page with a live SQL console and an Arrow round trip, bilingual (en / zh-Hans).
- `docs`: the documentation site; also bilingual, and the entry point of the Pages site.
